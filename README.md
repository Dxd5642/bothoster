# BotHoster

### Веб-сервис конструирования и автоматического развёртывания ботов для социальных сетей

**BotHoster** — веб-платформа, предназначенная для упрощения процесса создания, настройки, запуска и управления ботами для социальных сетей.

Проект разрабатывается в рамках темы: **«Разработка веб-сервиса конструирования и автодеплоя ботов для социальных сетей»**.

Основная идея проекта — предоставить пользователю единый интерфейс, с помощью которого можно создавать ботов, настраивать их поведение и автоматически развёртывать их без необходимости вручную настраивать серверное окружение для каждого экземпляра.

## О проекте

Создание и развёртывание ботов для социальных сетей часто требует от пользователя знания программирования, настройки серверов, работы с API сторонних платформ и самостоятельного сопровождения приложений.

BotHoster призван упростить этот процесс за счёт предоставления единой веб-платформы для управления ботами.

Пользователь сможет взаимодействовать с системой через веб-интерфейс, создавать и настраивать ботов, управлять их параметрами и контролировать состояние развёрнутых экземпляров.

Система проектируется с учётом разделения пользовательской и административной функциональности, безопасного хранения данных и возможности дальнейшего расширения поддерживаемых социальных платформ.

### Актуальность проекта

Автоматизация создания и развёртывания программных ботов позволяет сократить количество ручных операций, упростить управление приложениями и сделать инструменты автоматизации доступнее для пользователей без глубоких технических знаний.

Разработка подобного сервиса предполагает решение задач веб-разработки, управления пользовательскими данными, интеграции со сторонними API, автоматизации развёртывания и мониторинга запущенных приложений.

## Цель проекта

Разработать веб-сервис, обеспечивающий создание, настройку, автоматическое развёртывание и управление ботами для социальных сетей через единый пользовательский интерфейс.

## Основные задачи

Для достижения поставленной цели необходимо решить следующие задачи:

1. Разработать архитектуру веб-сервиса.
2. Реализовать регистрацию и авторизацию пользователей.
3. Разработать систему управления пользовательскими профилями.
4. Реализовать механизм создания и хранения конфигураций ботов.
5. Разработать интерфейс конструирования и настройки ботов.
6. Реализовать интеграцию с API поддерживаемых социальных сетей.
7. Разработать механизм автоматического развёртывания ботов.
8. Реализовать управление состоянием запущенных ботов.
9. Разработать административную панель.
10. Реализовать логирование, обработку ошибок и тестирование основных компонентов системы.
11. Обеспечить безопасное хранение пользовательских данных и секретов интеграций.

## Архитектура проекта

На текущем этапе проект ориентирован на модульную монолитную архитектуру.

Backend реализуется на FastAPI. Основная бизнес-логика разделяется на функциональные модули, взаимодействующие с PostgreSQL и Redis.

### Общая схема взаимодействия

```text
                 Пользователь
                       |
                       v
                Веб-интерфейс
                       |
                       v
                  FastAPI
                       |
          +------------+------------+
          |            |            |
          v            v            v
     Auth / Users   Bot Service   Admin
          |            |            |
          v            v            v
        Redis        SQLite       SQLite
                       |
                       v
               Deploy Service
                       |
                       v
             Социальные платформы
```

Схема отражает логическое разделение компонентов. Конкретная реализация сервиса развёртывания и интеграций будет уточняться по мере разработки.

### Основные компоненты

**Auth Service**

Отвечает за регистрацию, авторизацию, создание и завершение пользовательских сессий.

**User Service**

Обеспечивает работу с профилями пользователей и пользовательскими настройками.

**Bot Service**

Отвечает за создание, настройку и управление ботами.

**Deploy Service**

Предназначен для автоматизации развёртывания ботов и управления их жизненным циклом.

**Admin Service**

Обеспечивает административное управление пользователями и ресурсами платформы.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/Dxd5642/bothoster.git
cd bothoster
```


### 2. Создание виртуального окружения

Windows:

```bash
python -m venv venv
```

Активация:

```bash
venv\Scripts\activate
```

Linux / macOS:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Установка зависимостей

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Создайте файл `.env` в корне проекта на основе `.env.example`.

```bash
cp .env.example .env
```

### 5. Запуск Redis

Убедитесь, что Redis запущен и доступныпо адресу, указанному в `.env`.


### 6. Применение миграций базы данных

```bash
alembic upgrade head
```

### 7. Запуск FastAPI

Для локальной разработки:

```bash
uvicorn main:app --reload
```

После запуска API будет доступен по адресу (установлены параметры по умолчанию):

```text
http://127.0.0.1:8000
```

Интерактивная документация Swagger UI:

```text
http://127.0.0.1:8000/docs
```

Альтернативная документация ReDoc:

```text
http://127.0.0.1:8000/redoc
```

Конфигурация приложения осуществляется через переменные окружения.

PORT=8000
REDIS_HOST="127.0.0.1"

Это пример конфигурации для разработки, а не гарантированно готовый конфиг текущей версии приложения. Названия переменных должны соответствовать фактической реализации настроек.

**Важно:**

* Не храните реальные пароли, секретные ключи и токены в Git.
* Файл `.env` должен быть добавлен в `.gitignore`.

### Миграции

Для управления изменениями схемы базы данных используется Alembic.

Создание миграции:

```bash
alembic revision --autogenerate -m "migration_name"
```

Применение миграций:

```bash
alembic upgrade head
```

Откат на одну ревизию:

```bash
alembic downgrade -1
```

Перед применением миграций в production рекомендуется проверять сгенерированный файл миграции и выполнять резервное копирование данных.
